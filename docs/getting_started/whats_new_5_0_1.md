# 🆕 v5.0.1 更新说明（即将发布）

> 这是 5.0.1 的预告说明，随安装包一起发布；5.0.0 的功能请看 [v5.0 更新说明](whats_new_5_0.md)。

## 一、稳定性与安全
- **设备身份校验 403 的根因修复**：此前设备密钥用「电脑名 + 用户名」加密，电脑名变化（如 macOS 在不同网络下 `.lan` / `.local` 切换）后会无法解密并重新生成密钥，导致授权服务器提示「设备密钥不一致」。现在密钥存储不再依赖电脑名，旧文件自动升级，无法解密的旧文件会被保留而不是覆盖。
- 激活失败时给出更清晰的提示，并附上可复制的诊断信息（不含任何密钥内容）。

## 二、统一群发
- **「忽略限流冷却」开关（默认关闭）**：默认遵守 Telegram 的限流冷却——被限流的账号自动休息、任务换下一个账号；打开前会列出风险并要求确认。
- **休息间隔真正生效**：每个账号连续发送一批（默认 20 条）后休息设定的秒数。
- **统一群发重构为两种方式**：**群聊群发**——不再输入目标，软件读取所选账号「已经加入」的群并列出来（可搜索、全选 / 勾选），每个群只由一个在群里的账号发送；账号被封 / 被禁言 / 限流时自动改派给同群其他账号；按账号与代理线路控制并发；文字 / 图片 / 文件 / 语音条 / 投票 / 转发 / 撤回等原有发送能力全部可用。**频道评论**——输入频道，可选「评论前先让账号加入频道」（有的频道不用加入就能评论，有的必须先加入）。私信请用「私信群发」。
- 「秒评未来帖」监听模式补上了限流处理。

## 三、批量加群
- **按群分配加群**：每个群只安排指定数量的账号去加，已在群里的账号不重复加，按各账号今日剩余入群额度均衡分配，开始前会告诉你超出额度的部分大约还需要几天。
- **群质量漏斗**：评估群的质量（高价值 / 中等 / 低价值 / 待定 / 不可用，附原因）；**只做推荐，加不加由你决定**。**黑名单**（加群时默认跳过，防误加）与**白名单**（永不推荐退群）；评估结果表默认一个都不勾选，由你勾选后再决定「加入黑名单」或「只保留勾选的作为目标」。
- 批量加群与统一群发打通：加群后自动记录「谁在哪个群」，群发直接按这份关系分配。

## 四、MCP：45 项 → 53 项，软件里能做的基本都能被 Agent 调度
新增：`tg_agent_llm`（Agent 代答，见下）、`tg_smart_broadcast`（智能群发）、`tg_group_funnel`（评估 / 黑白名单 / 加群 / 退群）、`tg_join_and_verify`（加群并自动过验证，含点链接 / 跳转私聊机器人）、`tg_create_bot`（通过 @BotFather 创建机器人）、`tg_spambot_appeal`（@SpamBot 逐步申诉对话，如实作答）、`tg_unified_send`（统一群发完整能力）、`tg_manage_accounts`（账号登录 / 导入 / 状态 / 设备 / 两步验证）。
修复：`tg_stop_task` 现在真的会停止任务（并可按任务编号只停一个）；`tg_account_warmup` 现在真正执行（需提供要浏览的频道）。
完整列表见 [MCP 工具参考](../mcp/03_tools_reference.md)。

## 五、设置里的新选项
- **账号风控额度由你决定**（设置 → 🛡 账号风控额度）：保持默认的「按号龄分阶段限额」（保护新号），改成「自定义全局额度」（每个账号统一用你填的私信 / 群内发言 / 拉人 / 进群上限），或「关闭额度拦截」（不限额，风险自负，会有明显提示）。改动立即生效，MCP / Agent 同样遵循。
- **没有 AI API Key 也能用 AI 炒群**：AI 供应商可选「mcp_agent」，由接入的 AI Agent 通过 MCP 代答（AI 炒群的发言与剧本生成、AI 接待、入群验证的 AI 兜底）。需要 Agent 在线并持续处理请求；每条回复消耗 Agent 一侧的 Token，且比直连 API 慢。私信自动回复、频道克隆改写、机器人探查、运营分析仍需要 API Key。
- **「手机端机器人」页**：@wchjbot 改称「监控群发获客机器人」，新增「极速频道搬运机器人」@whitemaobot，以及机器人定制开发的联系入口。

## 六、开始前预检、名片与内联机器人消息、强拉加群重构（5.0.1 检阅期新增）
- **开始前预检**：批量加群、模拟阅读、群聊群发、频道评论、私信群发、强拉加群点「开始」后先弹预检面板——账号有没有被冻结 / 限制、风控额度还剩多少、各账号已加入多少群还能再加多少、AI 是否就绪、预计耗时（含「按每日额度约需几天」）；预检过程有进度条与实时步骤，可取消；异常账号自动排除。
- **养号额度拦住时**：直接说明原因（账号处于哪个阶段、24 小时上限与已用），并一键跳到「设置 → 账号风控额度」。
- **并发提醒**：「同一代理线路上同时发送的账号数」超过 3 而账号还在用本机网络时提醒（可忽略），并可一键跳到代理管理。
- **联系人名片 / 内联机器人消息**：群聊群发、频道评论、私信群发都能发联系人名片；也能发 `@PostBot 帖子ID` 这类内联机器人的图文 + 按钮消息（带「via」；内容须是发送账号有权使用的）。MCP 的 `tg_unified_send` 同步支持 `contact_card` / `inline_query`。
- **发送结果可信**：群发后回读核实消息确实存在，日志写出消息 id 与耗时；限流不再在后台悄悄等待。
- **已加入但无法发言的群**：扫描时单独列出，按原因分为「被管理员单独禁言（可退群重进再过验证）」与「群全员禁言（重进也没用）」，支持筛选、加黑名单；退群重进的结果窗口可把仍被禁言的群交给其他账号、记白名单或黑名单。**退群前会先确认账号当天的入群额度，额度不够就不退**，避免退了回不去。
- **批量加群**：支持「先加入频道再点完成验证」类入群验证；账号早就在群里却被禁言时可选「退群重进再过验证」；「🚪 退出黑名单里的群」批量退群；群发时发现没有可用账号的群自动进「待补群清单」。
- **强拉加群重构**：开始前核实账号在目标群里且有拉人权限；拉入后回读对方真的在群里（Telegram 对隐私受限的人不报错而是悄悄不拉，旧版会把它算成功）；私信邀请只算「已发邀请」；每个账号独立间隔 / 冷却 / 人数上限；加联系人重试默认关闭且不再暴露你的手机号；失败原因用人话，可复制失败名单。
- **运行日志**：右上角「运行日志」弹出独立大窗口，可筛选 / 搜索 / 保存；日志里的乱码文字已修复。

## 七、需要知道的限制
- 入群受每账号每日额度限制，大批量需要多天；Telegram 对单账号加入的群数量也有上限。
- 邀请链接无法匹配「账号—群」关系（用群 @用户名或入群后重新扫描）。
- 千级账号同时在线的内存与连接数、真实吞吐与封号率取决于账号质量、代理与节奏，没有统一保证。
- 内联机器人消息能否被多个账号使用取决于机器人（例如 PostBot 的帖子通常只有创建它的账号能用）。
- 「退群重进」只对有公开链接的群生效，重新加入会占用入群额度。
